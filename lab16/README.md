## Опис

Робота показує, як кодувати відео через ffmpeg, вимірювати якість результату (PSNR, SSIM) і перевіряти, чи вимірювання взагалі коректне. Заготовку `lab16.py` доповнено трьома функціями:

- `encode` — кодує еталонний кліп вибраним кодеком, повертає шлях, час і розмір файлу;
- `measure` — порівнює файл з еталоном і повертає PSNR та SSIM;
- `ladder` — проганяє кілька значень CRF і збирає таблицю.

Для порівняння кодеків додано окремий скрипт `task5.py`.

## Вимоги

- Python 3.9+, пакети `numpy`, `matplotlib`, `pillow`, `scikit-image`
- ffmpeg і ffprobe у PATH (збірка gyan.dev 9.1 з libx264, libx265, libsvtav1)

## Запуск

```
python lab16.py     # тести, драбинка CRF, графік rd.png, неправильне вимірювання

```

Перший запуск сам створює еталонний кліп `work/src.mkv` (1280×720, 30 кадр/с, 5 с, кодек ffv1 без втрат).

## Висновок

1. **Контейнер і кодек — різні речі.** Усередині mp4 лежить потік H.264, H.265 або AV1. Еталонний кліп має великий бітрейт, бо він збережений без втрат кодеком ffv1 і не стиснутий.

2. **Вибір crf.** Знижувати crf вигідно лише до певної межі. Перехід від crf 40 до 33 коштує +71 КБ за +3,05 дБ, а від 23 до 18 — +1194 КБ за +1,13 дБ. Для відео в інтернеті розумний вибір — **crf 23**: PSNR майже 40 дБ, SSIM 0,968, файл утричі менший за crf 18. Якщо важлива економія трафіку, допустимий crf 28.

3. **Вимірювання легко зіпсувати.** Без вирівнювання міток часу, діапазону яскравості та формату пікселів PSNR між crf 18 і crf 40 відрізняється лише на 0,29 дБ замість справжніх 8,10 дБ. Хибний висновок звучав би так: «налаштування якості ні на що не впливають». Ознака зіпсованого вимірювання: число майже не змінюється при сильній зміні налаштувань.

4. **Порівнювати кодеки треба за однаковою якістю, а не за однаковим crf.** Шкали CRF у кодеків різні. При 39,5 дБ H.265 дає файл ≈322 КБ проти ≈529 КБ у H.264, тобто приблизно на 39% менше. `<<додайте результат AV1 після нового прогону>>`

5. **Обмеження висновків.** Розмір при 39,5 дБ отримано інтерполяцією, а не прямим вимірюванням. PSNR і SSIM порівнюють пікселі, а не враження глядача: файл може мати кращий PSNR і виглядати гірше. Еталонний кліп — рівна панорама, найзручніший матеріал для нових кодеків. На відео з хаотичним рухом виграш буде помітно меншим. Один кліп не дає права на загальне твердження про перевагу кодеків.
